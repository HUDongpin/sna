# Researcher workflow implementation plan

> For agentic workers: use subagent-driven-development and test-driven-development. The user authorized implementation on 2026-10-26 after selecting questionnaire/scale researchers as the first audience.

**Goal:** A researcher can inspect and confirm their own questionnaire dataset, run an analysis independent of a browser connection, recover the result, and export a complete, reviewable research package.

**Architecture:** Preserve the existing pinned NPN/EBICglasso profile and binary NCT scope. Add R-authoritative inspection/validation and explicit variable mapping; durable asynchronous jobs use an isolated filesystem store and independent runner locally, and private Google Cloud Storage plus Cloud Tasks on the configured production worker. Reuse the existing authenticated HTTPS proxy boundary. All published output remains aggregate-only. No deployment or participant recruitment is authorized by this implementation request.

**Tech stack:** Next.js, TypeScript, React, pinned R 4.4.2 and renv; Google Cloud client libraries for production durability.

## Shared contracts

- `lib/open-sna-workbook-selection.ts` owns `OpenSnaSelection`: `{ items: Array<{ column: string; id: string; community: string; reverse: boolean }>; groupColumn: string }`. Keep 6–40 items, 2–8 communities with 3–12 items each, 1–5 responses, max 5,000 rows, 64 columns, one sheet, and at least 20 complete rows per group. IDs/community codes are bounded ASCII identifiers; original column headers may be bounded Unicode text. Exclude IDs from automatic suggestions; explicit confirmation is required. Reverse scoring is `6 - x` only when selected and is recorded in provenance. Selection is applied identically in validation and estimation; no selection retains the legacy CLI behavior.
- R `--mode inspect` emits `OpenSnaInspectionResult` from `lib/open-sna-workbook-selection.ts`: `{ schemaVersion: "1.0", inputFingerprint, originalRows, columns: [{ name, missingCount, eligibleItem, eligibleGroup, suggestedCommunity: string | null }], suggestedSelection: OpenSnaSelection | null }`. No raw responses, filenames or sheet names. R `--selection <JSON path>` is accepted in validation and analysis; inspect does not accept selection. Type guards are strict and bounded.
- Validation retains the legacy `1.0` result for no selection; mapped validation emits `1.1` with the existing summary plus top-level `selection`. Public validate always uses confirmed selection and returns its normalized form. The file fingerprint is SHA-256 of original bytes. Jobs also compare a canonical selection fingerprint.
- Aggregate result schema `1.2` adds `source.selection` and the complete `subgroupComparison.edgeDifferences` table (all p(p-1)/2 tests); retain `strongestEdgeDifferences` as a presentation subset. Reader accepts legacy `1.1` without fabricating missing evidence. New reports explicitly label incomplete legacy NCT exports. New R results use `1.2`; bundled demo stays readable.
- `POST /api/open-sna/inspect`: multipart workbook. `POST /api/open-sna/validate`: workbook + selection JSON. Both clean temporary uploads before responding and return bounded public errors.
- `POST /api/open-sna/jobs`: workbook, selection JSON, inputFingerprint, bootstraps (100/500/1000), permutations=1000, locale, UUIDv4 `Idempotency-Key`. Revalidate before accepting. Returns 202 `{jobId,status,pollAfterMs,expiresAt}`. Same bytes/selection/settings/key returns existing job; changed data/settings returns 409.
- `GET /api/open-sna/jobs/:id`: queued/running/succeeded/failed/cancelled/expired; bounded code only. `GET .../result`: 200 strict aggregate; 409 pending/finalizing; 410 expired; 404 unknown. `DELETE .../:id`: cancel with terminal state protected against late writers. IDs are opaque bearer capabilities and must not enter URLs to third parties or logs.
- Jobs last 24 hours; R execution limit 600 seconds, queue dispatch 900 seconds, one active execution. Cloud Run admits eight concurrent HTTP requests so short status/cancel operations can proceed while the single queued R task runs. Atomic claims, expiring leases, bounded attempts, and fenced terminal writes. Delete input + selection on all terminal outcomes, lifecycle expiry as backup. Store no original filenames, raw diagnostics, or source values in job metadata. Production must fail closed if durability configuration is absent; never launch untracked work inside a Vercel request.
- Browser stores only job ID, locale and timestamps. Poll 2s queued/5s running, one request at a time; reconnect automatically, restore after reload, provide task-ID recovery, cancellation and explicit dismissal. Network errors are reconnecting states, not failed analyses. Reference results cannot overwrite recovered/uploaded results.
- R remains authoritative; optional LUNA finalization is persisted once per job, with lease/conditional writes so concurrent reads cannot create duplicate finalized outcomes. Absence/failure of AI leaves a successful R result usable.
